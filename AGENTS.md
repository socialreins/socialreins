# AGENTS.md: socialreins/socialreins

Next.js frontend for SocialReins (socialreins.com) and the main repo of the project (its README is the entry point for users): the marketing landing page with the waitlist now, the logged-in app later, in one codebase. The backend is the Rust API in github.com/socialreins/brain, included here as the git submodule `brain/` so one `git clone --recurse-submodules` gets everything. Change brain through a PR in socialreins/brain, then open a PR here that bumps the submodule (`git submodule update --remote brain`). `brain/` is excluded from ESLint, TypeScript, Next.js file tracing and `.dockerignore`: the web Dockerfile never needs it.

## Rules
- No em dashes in any text: copy, code comments, docs, commit messages, PR text. Use a comma, colon, full stop or two sentences. En dashes in numeric ranges are fine.
- Ship via a branch and a PR to `main`, and merge only with green CI.
- Never force-push.
- Never commit secrets. `.env*` is gitignored except `.env.example`. `NEXT_PUBLIC_*` values ship to the browser, so never put a secret in one.
- Landing copy states only confirmed product facts. No prices, user counts, testimonials or dates.

## Next.js
This is Next.js 16 (App Router, Turbopack, `cacheComponents`). APIs differ from older versions: read the guide in `node_modules/next/dist/docs/` before writing code, and heed deprecation notices.

## Run
```
cp .env.example .env.local
npm ci
npm run dev
npm run lint && npm run typecheck && npm test
npm run build && npm run test:e2e   # Playwright serves the production build on :3000
```

## Layout
- `app/page.tsx` landing page; `app/(app)/` the logged-in app, a route group, so its pages have no prefix (`/home`, `/posts`, `/connections`; old `/app/*` links redirect in `next.config.ts`): `layout.tsx` wraps every page in `components/app-shell.tsx` (sidebar with the logo at the top (mark and name, only the mark on the icon rail), the theme switch and the account with the role in the current team at the foot; checks the session once and shares it with `useSession()`; the top bar in `components/top-bar.tsx` starts its breadcrumb with the team switcher, whose menu ends with the plan ("Free plan", Upgrade links to `/billing`, a Plans page saying paid plans are coming), then the set switcher only on the pages the picked set filters (`set: true` on the page in the shell's `nav`: Home, Posts, Calendar, Lists, Accounts; its button carries `aria-label="Set: <name>"` and shows only the name), then the page's title: `PageHeader` renders its `h1` into the bar's last crumb through `PageTitle` in `components/page-title.tsx` (a portal into the slot the shell shares as `TitleSlot`), so the name is said once and the page itself has no big heading; a `back` page is a crumb link before it from `sm` up and a link on the page on phones), and `/app` redirects to `/app/posts`. The sidebar groups its links under Publish, Engage, Workspace, Profile settings and Admin (site admins only); each group heading is a disclosure button, open or closed per group in localStorage (`sidebar-group:<label>`), and the group holding the current page always stays open. Theme: Light, Dark or System (default) in localStorage `theme` (`components/theme.tsx`), set as `data-theme` on `<html>` before paint by an inline script in `app/layout.tsx`; the dark tokens are redefined under `:root[data-theme="dark"] .app-root` in `app/globals.css`, so only the signed-in app goes dark and the landing and sign-in pages stay light. From `md` up a button collapses the sidebar to an icon rail (`sidebar-collapsed` in localStorage; link names stay as sr-only text plus a `title`); small screens keep the menu button. `components/passkey-prompt.tsx` is the "Add a passkey" `<dialog>` the shell opens when `listPasskeys()` returns an empty list (not on `/app/security`, not without WebAuthn, not when the list fails); closing it any way hides it for 7 days (`passkey-prompt-snoozed-at`), and `/welcome`'s "Skip for now" sets the same snooze. `profile.tsx` is `/app/profile` (name, email, links to Sign-in and security and Passkeys) with a form that changes the name (`updateName`, `PATCH /auth/me`, checked first with `cleanName`: trimmed, 1 to 80 characters) and puts brain's answer in the session with `setUser`, so the sidebar's account shows it. `components/ui.tsx` holds the icons and `PageHeader`; the `.btn`, `.field`, `.card`, `.badge` and `.tone` classes live in `app/globals.css`.
- `app/login/` and `app/signup/` log in or create an account with Google (shown only when brain's `/auth/providers` says so), a passkey (login only), or an email link on their own `/email` pages (sign-up also asks for a name). Login never creates an account, so only the sign-up pages show the Terms line. A sign-up brain refuses goes on its waitlist: by Google it lands on `/signup?waitlisted=1`, shown once as a status note and dropped from the URL; by email the check-your-email note says the email may say so instead. There are no passwords. `app/welcome/` follows a new sign-up and offers to add a passkey. `app/privacy/` and `app/terms/` are the public policy pages (`components/legal-page.tsx`). `app/post-types/` is the public "What you can post where" table (post types by network, kept by hand in line with `limits` and brain). `app/contact/` is the public contact form (`components/contact-form.tsx`, `lib/contact.ts`, `POST /v1/contact`); the site shows no email address, only links to `/contact`. `components/turnstile.tsx` (`useTurnstile`) renders Cloudflare Turnstile on the login email and contact forms (not the waitlist) when `/auth/providers` returns a `turnstile_site_key`, sends its single-use token as `turnstile_token` and resets after each submit; a null key means Turnstile is off. The CSP in `proxy.ts` allows `https://challenges.cloudflare.com` in script-src and frame-src. The app shell checks the session client-side. `app/waitlist/verify/` is where the waitlist confirmation email links, with `?token=` (`components/waitlist-verify.tsx`): a "Confirm my email" button POSTs the token to brain's `/v1/waitlist/verify`, then shows "Your spot is confirmed" or, for a bad or missing token, a note to join again from the home page. It never confirms on page load, since mail scanners open links. `app/favicon.ico` is generated from `app/icon.svg` (16, 32 and 48 px).
- `components/` UI pieces. Client components: `waitlist-form.tsx`, `login-form.tsx`, `account.tsx`, `session-link.tsx`, `security.tsx` (the `/app/security` page, titled Sign-in and security: add and remove passkeys in `#passkeys`), `team-switcher.tsx` (in the app sidebar), `team.tsx` (`/app/team`: rename, members, invitations, delete), `invitation.tsx` (`/invitations/[token]`: preview and accept). `team-ui.tsx` holds their shared messages and status line. `connections.tsx` is `/app/connections`: connected accounts, the provider grid, the Bluesky app-password form, and a Connect link for each configured OAuth provider in `oauthProviders` (Threads, LinkedIn, X, TikTok, YouTube, and Facebook with Instagram as one "meta" card; an account's brain `status` is `ok`, `expiring` (the token ends within 7 days, at `token_expires_at`, and nothing renews it) or `reconnect` (expired or refused, also the older `reconnect: true` flag): `attention()` in `lib/connections.ts` reads it, the card shows a badge and a note with a Reconnect link for owners and admins, and `ReconnectNotice` lists the same accounts on Home and, for the ticked platforms, in the post editor), a full-page navigation to brain's `/connections/{provider}/redirect`; brain lands back with `?connected=` or `?connect_error=&provider=`, which the page shows once and drops from the URL (`lib/connections.ts`). A Meta login lands on `?pick=meta` instead when there is something new: owners and admins then get a picker of the Pages and linked Instagram accounts brain holds for 15 minutes (`GET|POST|DELETE /v1/connections/meta/pick`, never tokens), all checked, with Connect selected and Cancel. Avatars come from Bluesky's CDN, Meta's (`*.fbcdn.net`, `*.cdninstagram.com`) YouTube's (`yt3.ggpht.com`, `yt3.googleusercontent.com`) X's (`pbs.twimg.com`) or TikTok's (`*.tiktokcdn.com`, `*.tiktokcdn-us.com`), the only image sources the CSP in `proxy.ts` allows. `sets.tsx` is `/app/sets`: social sets with create, rename, delete (password or fresh sign-in) and restore (`lib/sets.ts`), one card of sets whose accounts show the `NetworkAvatar` from `connections.tsx` (a set of more than 8 folds into a `<details>`), and a quiet Recently deleted list below; `/app/connections` edits each account's sets. `api-tokens.tsx` is `/app/api-tokens` (owners and admins: list, create with a whole-team or one-set scope and an expiry, revoke; the new secret shows once, from component state only, and creating needs a fresh sign-in) on `lib/api-tokens.ts`, with `webhook.tsx` below it as a second section (the team webhook: set or change the URL, its `whsec_` secret shown once on create, send test, remove) on `lib/webhook.ts`. `posts.tsx` is `/posts` (the month as a list of days, with drafts) and `/calendar` (the month grid, a list of days below `lg`), both following the set filter (the default set, named All sets unless renamed, holds every account and shows every set's posts: brain's `GET /v1/posts` answers so for its id), each post marked with its platform icon, and `post-editor.tsx` is `/app/posts/new` and `/app/posts/[id]`. A new post picks its platforms ("Post to": every platform with an account in the set, ticked by default) with a character count per platform from `limits` in `lib/posts.ts` (brain's `crates/core/src/post.rs`), an optional "Customize for <platform>" text, and live warnings brain would refuse (Instagram or TikTok without media, too many images, YouTube without its one MP4 or MOV video or a title); YouTube takes the first line of the text as the video's title (100 characters) and the rest as the description (5000 bytes), counted separately by `Counts` and split by `youtubeText` in `lib/posts.ts`, a "YouTube visibility" select (Private by default, Unlisted, Public) is sent as `youtube: {privacy}` (a group's top-level `youtube`, which brain gives to its YouTube post only) and shown read-only on a saved YouTube post, and the editor says uploads may stay private whatever is chosen until Google audits the API project; two or more platforms save through `POST /v1/post-groups` (Facebook, Instagram, LinkedIn, YouTube and TikTok get an empty thread override, so only Bluesky, Threads and X post the thread; X counts 280 weighted characters with `xWeight` in `lib/posts.ts`, mirroring brain's: a link 23, CJK and emoji 2, and takes 4 images or one GIF or video), one through `POST /v1/posts`. A "First comment" box shows only when a ticked platform takes one (Facebook 8000 characters, Instagram 2200, LinkedIn 1250, YouTube 10000: `limits[p].comment` in `lib/posts.ts`, `null` elsewhere, checked by `checkComment`), with a count per platform and a "Customize the first comment for <platform>" text like the body's; a group sends it as `first_comment` with an empty override on the platforms that can't post one. brain posts it once right after the post is published and never retries, so a published post's page shows the text and, per account, `comment_status` and `comment_error` (a failed comment leaves the post published). A "Cover image" link shows only while exactly one link is attached that is not plainly an image and a ticked platform takes one (`limits[p].cover`: Instagram JPEG, Facebook and YouTube JPEG or PNG, checked by `checkCover`; TikTok can only pick a frame, so it and the rest get none); it is sent as `cover`, in a group only as an override on the platforms that take one. brain sets it on Facebook and YouTube after the video is live, so a published post's page shows `cover_error` per account (a failed cover leaves the post published). A saved post edits alone, keeps its platform and lists the rest of its group (`GET /v1/posts?group_id=`) with status and links, and "Take down all" there (shown when a published post is in the group) confirms once, then calls `DELETE /v1/posts/{id}` for each published post in turn (`takeDownAll`; a brain rate limit stops the run), reports each platform and offers a retry for the ones still up. Then: compose, a thread of up to 25 follow-up posts sent as `thread` and previewed in order, each post with up to 4 image links in the shared `ImageLinks` fieldset (any public https link, Google Drive share links included: brain downloads them at publish time; its hint says LinkedIn also takes one PDF, alone, as a document titled by the text's first line), schedule, publish now with polling, delete or take down, read-only once it leaves draft or scheduled with a link to each published follow-up from `targets[].parts`); both use `lib/posts.ts`. The editor hints at each platform's media types and the cover type by the link's extension (`checkMediaTypes`, `coverTypeHint`, mirroring brain's probe checks), never blocking a save; brain reads the files when the post is saved and answers `media_type_not_supported`, `mixed_media`, `media_too_large`, `invalid_cover_type`, `cover_too_large` or `tiktok_privacy_not_offered`, shown through `postMessages`. With TikTok ticked the editor shows `tiktok-settings.tsx` (TikTok's Direct Post guidelines: the account's live creator info from `GET /v1/connections/{id}/tiktok`, a privacy select with no default, comment, duet and stitch off, the content disclosure with Your brand and Branded content, an AI-generated flag, and the consent declaration above the buttons); saving is blocked until a level is chosen, the disclosure is complete and the account can post, mirrored by `checkTikTok` and sent as `tiktok`. `lists.tsx` is `/app/lists` (create team-wide or for one set, rename, delete) and `/app/lists/[id]` (posts in order as Part N, Move up and Move down, remove, add a post of the list's set) on `lib/lists.ts`; calendar chips and drafts show `Part N · list`, and the editor's List select sends `list_id`, leaving out lists the post is already in since brain would move it to the end. `inbox.tsx` is `/app/inbox` and `/app/inbox/[inboxId]` (inboxes, items with Open/Done in `?state=` and the open item in `?item=`, reply, mark done; panes stack on small screens; the kind chips ask brain for `?kind=`, and the open list folds in the newest page every 30 seconds while the tab shows, via `mergeFresh` in `lib/inbox.ts`) with `inbox-editor.tsx` (create, edit, delete an inbox in a `<dialog>`), on `lib/inbox.ts`. `automations.tsx` is `/app/automations`, `/new` and `/[id]` (list with on/off switch and the run count brain's list carries, run history) with `automation-form.tsx` (the comment-to-DM form over brain's general trigger, conditions and actions), on `lib/automations.ts`; `postUri` turns a Bluesky post link into the at:// URI brain matches, resolving handles only against the team's own accounts. `scope-fields.tsx` holds the shared accounts-or-set picker and keyword chips. The CSP in `proxy.ts` allows images from `https://cdn.bsky.app` for avatars only. The admin console is `/admin`, for site admins only (`is_admin` from `/auth/me`; the account menu shows its Admin console link only then, the shell sends anyone else to `/home`, and brain answers 403 `forbidden`, which every page shows as "You don't have access to the admin panel."). It has its own sidebar (`adminNav` in `app-shell.tsx`: Overview, Users, Teams, Waitlist, Sign-up settings; Overview's `/admin` marks only itself, like Home) and five pages on `lib/admin.ts` (brain's `/v1/admin/*`). `admin-overview.tsx` is `/admin`: cards for users (new in 7 days), teams, the waitlist (verified, approved), connected accounts per network and posts by status, the first three linking to their pages (`GET /v1/admin/overview`). `admin-lists.tsx` is `/admin/users` and `/admin/teams`: one `AdminList` with a search box, a table, "Showing X to Y of Z" and Previous and Next, the search and page kept in `?q=&limit=&offset=` (`parsePage` keeps a hand-edited URL within what brain accepts: a `limit` or `offset` that is not a safe whole number, or a `limit` outside 1 to 200, falls back to its default, `limit` 50 and `offset` 0; past the end, Previous goes straight to the last page with rows). `admin.tsx` is `/admin/waitlist`: totals (the Approved one comes from the overview, since the waitlist answer has none), an All / Verified / Not verified filter in `?verified=`, a search by email in `?q=`, and the signups table with Approve (`POST /v1/admin/waitlist/{id}/approve`; `approvalText` says whether the email was sent, the entry was already approved, or the mail failed and the person must be told another way) and Remove (`DELETE`, asks first and warns when the entry is approved), both changing the row and the totals in place, but only in the list the action started on; brain's `not_found` (another admin removed the entry) is said so and drops the row, and the Approved total shows a dash when the overview fails; it also holds the console's shared `SearchBox` and `Forbidden`. `admin-settings.tsx` is `/admin/settings`: who can create an account (`open`, `closed` or `domains` with a list of domains and addresses, read by `parseDomains`), whether the current value comes from the server's environment or was saved here, a second question before opening sign-up to everyone, and brain's `reauth_required`, `invalid_domains` and `invalid_mode` explained (`GET|PUT /v1/admin/settings/signup`; the list is sent with every mode so it survives a change of mode: the typed list with `domains`, the last saved one with the other two, whose box is hidden). `GitHubMenu` in `components/github-link.tsx` is the header's GitHub menu (the main repo and the brain), built like `socials-menu.tsx` on the client dropdown `components/menu.tsx`: the summary shows the total stars across the org's public, non-archived repos, the menu each listed repo's count, all from one request to the org's repo list (`fetchStars` in `lib/github.ts`, cached with `use cache`, no number when GitHub fails).
- `lib/teams.ts` calls brain's `/v1/teams`, `/v1/current-team`, `/v1/team*` and `/v1/invitations/{token}` through `api()` in `lib/auth.ts`. `mayChange` and `grantable` mirror brain's role rules so the UI hides what the caller's role can't do. Brain's magic link always lands on `/app`, so an invitation asks a signed-out visitor to sign in and open the link again.
- `lib/waitlist.ts` calls `POST {apiUrl}/v1/waitlist`. 200 means joined (a duplicate also returns 200) and brain emails a link to confirm the spot, 422 invalid email, 429 rate limited. `waitlistCount` reads `GET /v1/waitlist/count` (everyone, confirmed or not); the form shows it under the input, refetches it after a join and shows nothing on an error. `verifyWaitlist` posts the emailed token (no credentials): 200 verified, 422 `invalid_link`, 429 rate limited.
- `lib/auth.ts` calls brain's `/auth/link`, `/auth/me` (GET, and PATCH to change the name), `/auth/logout`, `/auth/providers` and `/auth/passkeys*`; Google sign-in is a full-page navigation to `{BRAIN_URL}/auth/google/start?next=` with `credentials: "include"`, mapping brain's error codes to a `Failure` union. `lib/webauthn.ts` converts WebAuthn options and credentials to and from brain's base64url JSON. The session cookie is HttpOnly on the API host, so Next server code cannot see it: auth checks run in the browser.
- brain's URL is the run-time `BRAIN_URL` (`lib/brain-url.ts`), never baked into the build: `app/config.js/route.ts` sets `window.__BRAIN_URL`, which the root layout loads with `beforeInteractive` so `apiUrl` in `lib/waitlist.ts` sees it, and `proxy.ts` puts its origin in the CSP `connect-src`.
- Self-host: `docker-compose.yml` (images by default; `docker-compose.build.yml` builds brain from `./brain`) and `.env.example` (every variable), documented in README "Self-host". `.github/workflows/image.yml` publishes `ghcr.io/socialreins/web`.
- Tests: `tests/unit` (vitest), `tests/e2e` (Playwright).
