# AGENTS.md: socialreins/web

Next.js frontend for SocialReins (socialreins.com) and the main repo of the project (its README is the entry point for users): the marketing landing page with the waitlist now, the logged-in app later, in one codebase. The backend is the Rust API in github.com/socialreins/brain.

## Rules
- No em dashes in any text: copy, code comments, docs, commit messages, PR text. Use a comma, colon, full stop or two sentences. En dashes in numeric ranges are fine.
- Ship via a branch and a PR to `main`, and merge only with green CI.
- Never force-push.
- Never commit secrets. `.env*` is gitignored except `.env.example`. `NEXT_PUBLIC_*` values ship to the browser, so never put a secret in one.
- Landing copy states only confirmed product facts. No prices, user counts, testimonials or dates.

## Next.js
This is Next.js 16 (App Router, Turbopack, `cacheComponents`). APIs differ from older versions: read the guide in `node_modules/next/dist/docs/` before writing code, and heed deprecation notices.

## Run
```
cp .env.example .env.local
npm ci
npm run dev
npm run lint && npm run typecheck && npm test
npm run build && npm run test:e2e   # Playwright serves the production build on :3000
```

## Layout
- `app/page.tsx` landing page; `app/app/` the logged-in app: `layout.tsx` wraps every page in `components/app-shell.tsx` (sidebar, team switcher, account; checks the session once and shares it with `useSession()`), and `/app` redirects to `/app/posts`. The sidebar groups its links under Publish, Engage, Workspace, Profile settings and Admin (site admins only); each group heading is a disclosure button, open or closed per group in localStorage (`sidebar-group:<label>`), and the group holding the current page always stays open. From `md` up a button collapses the sidebar to an icon rail (`sidebar-collapsed` in localStorage; link names stay as sr-only text plus a `title`); small screens keep the menu button. `components/passkey-prompt.tsx` is the "Add a passkey" `<dialog>` the shell opens when `listPasskeys()` returns an empty list (not on `/app/security`, not without WebAuthn, not when the list fails); closing it any way hides it for 7 days (`passkey-prompt-snoozed-at`), and `/welcome`'s "Skip for now" sets the same snooze. `profile.tsx` is `/app/profile` (name, email, links to Sign-in and security and Passkeys) with a form that changes the name (`updateName`, `PATCH /auth/me`, checked first with `cleanName`: trimmed, 1 to 80 characters) and puts brain's answer in the session with `setUser`, so the sidebar's account shows it. `components/ui.tsx` holds the icons and `PageHeader`; the `.btn`, `.field`, `.card`, `.badge` and `.tone` classes live in `app/globals.css`.
- `app/login/` signs in or creates an account with Google (shown only when brain's `/auth/providers` says so), an email link, or a passkey. There are no passwords. `app/welcome/` follows a new sign-up and offers to add a passkey. `app/privacy/` and `app/terms/` are the public policy pages (`components/legal-page.tsx`). `app/contact/` is the public contact form (`components/contact-form.tsx`, `lib/contact.ts`, `POST /v1/contact`); the site shows no email address, only links to `/contact`. `components/turnstile.tsx` (`useTurnstile`) renders Cloudflare Turnstile on the login email and contact forms (not the waitlist) when `/auth/providers` returns a `turnstile_site_key`, sends its single-use token as `turnstile_token` and resets after each submit; a null key means Turnstile is off. The CSP in `proxy.ts` allows `https://challenges.cloudflare.com` in script-src and frame-src. The app shell checks the session client-side. `app/waitlist/verify/` is where the waitlist confirmation email links, with `?token=` (`components/waitlist-verify.tsx`): a "Confirm my email" button POSTs the token to brain's `/v1/waitlist/verify`, then shows "Your spot is confirmed" or, for a bad or missing token, a note to join again from the home page. It never confirms on page load, since mail scanners open links. `app/favicon.ico` is generated from `app/icon.svg` (16, 32 and 48 px).
- `components/` UI pieces. Client components: `waitlist-form.tsx`, `login-form.tsx`, `account.tsx`, `session-link.tsx`, `security.tsx` (the `/app/security` page, titled Sign-in and security: add and remove passkeys in `#passkeys`), `team-switcher.tsx` (in the app sidebar), `team.tsx` (`/app/team`: rename, members, invitations, delete), `invitation.tsx` (`/invitations/[token]`: preview and accept). `team-ui.tsx` holds their shared messages and status line. `connections.tsx` is `/app/connections`: connected accounts, the provider grid, the Bluesky app-password form, and a Connect link for each configured OAuth provider in `oauthProviders` (Threads, LinkedIn, and Facebook with Instagram as one "meta" card), a full-page navigation to brain's `/connections/{provider}/redirect`; brain lands back with `?connected=` or `?connect_error=&provider=`, which the page shows once and drops from the URL (`lib/connections.ts`). A Meta login lands on `?pick=meta` instead when there is something new: owners and admins then get a picker of the Pages and linked Instagram accounts brain holds for 15 minutes (`GET|POST|DELETE /v1/connections/meta/pick`, never tokens), all checked, with Connect selected and Cancel. Avatars come from Bluesky's CDN or Meta's (`*.fbcdn.net`, `*.cdninstagram.com`), the only image sources the CSP in `proxy.ts` allows. `sets.tsx` is `/app/sets`: social sets with create, rename, delete (password or fresh sign-in) and restore (`lib/sets.ts`); `/app/connections` edits each account's sets. `api-tokens.tsx` is `/app/api-tokens` (owners and admins: list, create with a whole-team or one-set scope and an expiry, revoke; the new secret shows once, from component state only, and creating needs a fresh sign-in) on `lib/api-tokens.ts`, with `webhook.tsx` below it as a second section (the team webhook: set or change the URL, its `whsec_` secret shown once on create, send test, remove) on `lib/webhook.ts`. `posts.tsx` is `/app/posts` (month calendar, a list of days below `lg`, set filter, drafts, each post marked with its platform icon) and `post-editor.tsx` is `/app/posts/new` and `/app/posts/[id]`. A new post picks its platforms ("Post to": every platform with an account in the set, ticked by default) with a character count per platform from `limits` in `lib/posts.ts` (brain's `crates/core/src/post.rs`), an optional "Customize for <platform>" text, and live warnings brain would refuse (Instagram without media, too many images); two or more platforms save through `POST /v1/post-groups` (Facebook, Instagram and LinkedIn get an empty thread override, so only Bluesky and Threads post the thread), one through `POST /v1/posts`. A saved post edits alone, keeps its platform and lists the rest of its group (`GET /v1/posts?group_id=`) with status and links, and "Take down all" there (shown when a published post is in the group) confirms once, then calls `DELETE /v1/posts/{id}` for each published post in turn (`takeDownAll`; a brain rate limit stops the run), reports each platform and offers a retry for the ones still up. Then: compose, a thread of up to 25 follow-up posts sent as `thread` and previewed in order, each post with up to 4 image links in the shared `ImageLinks` fieldset (any public https link, Google Drive share links included: brain downloads them at publish time), schedule, publish now with polling, delete or take down, read-only once it leaves draft or scheduled with a link to each published follow-up from `targets[].parts`); both use `lib/posts.ts`. `lists.tsx` is `/app/lists` (create team-wide or for one set, rename, delete) and `/app/lists/[id]` (posts in order as Part N, Move up and Move down, remove, add a post of the list's set) on `lib/lists.ts`; calendar chips and drafts show `Part N · list`, and the editor's List select sends `list_id`, leaving out lists the post is already in since brain would move it to the end. `inbox.tsx` is `/app/inbox` and `/app/inbox/[inboxId]` (inboxes, items with Open/Done in `?state=` and the open item in `?item=`, reply, mark done; panes stack on small screens; the kind chips ask brain for `?kind=`, and the open list folds in the newest page every 30 seconds while the tab shows, via `mergeFresh` in `lib/inbox.ts`) with `inbox-editor.tsx` (create, edit, delete an inbox in a `<dialog>`), on `lib/inbox.ts`. `automations.tsx` is `/app/automations`, `/new` and `/[id]` (list with on/off switch and the run count brain's list carries, run history) with `automation-form.tsx` (the comment-to-DM form over brain's general trigger, conditions and actions), on `lib/automations.ts`; `postUri` turns a Bluesky post link into the at:// URI brain matches, resolving handles only against the team's own accounts. `scope-fields.tsx` holds the shared accounts-or-set picker and keyword chips. The CSP in `proxy.ts` allows images from `https://cdn.bsky.app` for avatars only. `admin.tsx` is `/app/admin`, for site admins only (`is_admin` from `/auth/me`; the sidebar shows the Admin group and its Waitlist link only then, and brain answers 403 `forbidden` to anyone else): waitlist totals, an All / Verified / Not verified filter in `?verified=`, and the signups table, on `lib/admin.ts` (`GET /v1/admin/waitlist`). `components/github-repos.tsx` is the GitHub menu with star counts (`lib/github.ts`, cached hourly with `use cache`).
- `lib/teams.ts` calls brain's `/v1/teams`, `/v1/current-team`, `/v1/team*` and `/v1/invitations/{token}` through `api()` in `lib/auth.ts`. `mayChange` and `grantable` mirror brain's role rules so the UI hides what the caller's role can't do. Brain's magic link always lands on `/app`, so an invitation asks a signed-out visitor to sign in and open the link again.
- `lib/waitlist.ts` calls `POST {apiUrl}/v1/waitlist`. 200 means joined (a duplicate also returns 200) and brain emails a link to confirm the spot, 422 invalid email, 429 rate limited. `waitlistCount` reads `GET /v1/waitlist/count` (everyone, confirmed or not); the form shows it under the input, refetches it after a join and shows nothing on an error. `verifyWaitlist` posts the emailed token (no credentials): 200 verified, 422 `invalid_link`, 429 rate limited.
- `lib/auth.ts` calls brain's `/auth/link`, `/auth/me` (GET, and PATCH to change the name), `/auth/logout`, `/auth/providers` and `/auth/passkeys*`; Google sign-in is a full-page navigation to `{BRAIN_URL}/auth/google/start?next=` with `credentials: "include"`, mapping brain's error codes to a `Failure` union. `lib/webauthn.ts` converts WebAuthn options and credentials to and from brain's base64url JSON. The session cookie is HttpOnly on the API host, so Next server code cannot see it: auth checks run in the browser.
- brain's URL is the run-time `BRAIN_URL` (`lib/brain-url.ts`), never baked into the build: `app/config.js/route.ts` sets `window.__BRAIN_URL`, which the root layout loads with `beforeInteractive` so `apiUrl` in `lib/waitlist.ts` sees it, and `proxy.ts` puts its origin in the CSP `connect-src`.
- Self-host: `docker-compose.yml` and `.env.example` (every variable), documented in README "Self-host". `.github/workflows/image.yml` publishes `ghcr.io/socialreins/web`.
- Tests: `tests/unit` (vitest), `tests/e2e` (Playwright).
